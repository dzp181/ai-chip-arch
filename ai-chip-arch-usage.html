AI 芯片架构专家

从模型负载出发，帮你把一颗 AI 训练 / 推理芯片的架构算清楚——算力阵列、存储带宽、片上互联、量化精度，一直到 PPA 取舍与部署瓶颈。

专家能做什么

算力阵列与数据流SIMD / SIMT / 脉动阵列 / 张量核，PE 映射与数据复用
存储层次与带宽SRAM / HBM / DDR 容量带宽、KV Cache、tiling 平衡
片上互联 NoC拓扑、仲裁、QoS 与 MoE/all-to-all 流量
量化与精度架构INT4 / FP8 / FP4、离群值、PTQ 与 QAT
模型-硬件协同GQA / FlashAttention / MoE / 投机解码的硬件诉求
PPA 与性能建模Roofline、TTFT/TPOT 分解、每瓦 token 测算

怎么用

  1. 打开专家中心
    在 WorkBuddy 左侧「专家」入口进入，找到「AI 芯片架构专家」。
  2. 直接对话
    点开专家即可开始提问，无需配置；首屏会带入一个示例问题。
  3. 用推荐提问起步
    点下方「试试这样问我」中的任一句，专家会按标准流程给出架构推导。
  4. 补充上下文
    给出模型规模、精度、目标指标、工艺与功耗上限等六要素，结论会更精确。

试试这样问我

我要做一颗大模型推理芯片，目标 70B 模型 INT4、单请求 TTFT 100ms 以内，请从算力阵列、存储带宽、KV Cache 到互联给我一套架构方案和瓶颈推导。
我们的 INT4 张量核算力有 200 TOPS，但端到端吞吐只有峰值的 18%，帮我判断瓶颈是内存带宽、NoC 争抢、kernel 启动开销还是数据流调度不理想。
对比三种 7B 大模型服务芯片架构：统一张量核阵列、注意力引擎加 MLP 专用阵列、权重静止脉动阵列，给出 PPA 与吞吐的取舍。

适合与不适合

适合

  • 架构方案选型、瓶颈定位与数值推导
  • 存储/带宽/互联的规格预算
  • 量化精度与算子融合的硬件影响
  • PPA 取舍、敏感度和可行性评估

不适合

  • 具体工艺库数据、PDK/第三方库复刻
  • EDA 物理实现、版图与 DFM
  • 驱动、内核与编译器的完整代码实现
  • 逆向他人受保护 IP
